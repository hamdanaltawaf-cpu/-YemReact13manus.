# Google OAuth في YemReact

## آلية الدخول

الموقع يستخدم **Google Identity Services** فقط. يرسل المتصفح Google ID Token إلى الخادم عبر الإجراء `auth.googleSignIn`. يتحقق الخادم من التوقيع ومن أن `audience` يطابق `GOOGLE_CLIENT_ID` باستخدام مكتبة Google الرسمية، ثم لا يقبل الحساب إلا إذا كان البريد مرفقًا وموثقًا من Google.

بعد التحقق، ينشئ الخادم جلسة JWT موقعة داخل cookie باسم `app_session_id`. الـcookie مضبوطة على `HttpOnly` و`SameSite=Lax`، وتستخدم `Secure` عند HTTPS أو في بيئة الإنتاج. لا تُخزن كلمات مرور أو رموز Google في قاعدة البيانات أو المتصفح.

## الصلاحيات

البريد `hamdanaltawaf@gmail.com` فقط، بعد التطبيع إلى أحرف صغيرة، يحصل على دور `admin`. جميع عناوين البريد الأخرى تحصل على دور `user`. يعتمد الخادم على الدور المخزن في قاعدة البيانات في كل طلب، وليس على أي قيمة ترسلها الواجهة.

| الدور | المتاح |
|---|---|
| `user` | حفظ وإزالة الرياكشنات، وصفحة الحساب والمحفوظات والمساهمات |
| `admin` | كل ما سبق، إضافةً إلى لوحة المحتوى وعمليات الإدارة |

## حماية الإدارة

حاجز الخادم يعيد الزائر أو المستخدم العادي من `/admin` و`/admin.html` إلى `/`. ويرجع أي طلب غير مصرح به إلى `/api/admin/*` بحالة `403`. وتستمر إجراءات tRPC الإدارية في التحقق من دور `admin` خادميًا، لذا لا تكفي معرفة رابط الواجهة للوصول إلى إدارة المحتوى.

## إعداد Google Client ID

1. افتح [Google Cloud Console](https://console.cloud.google.com/) وأنشئ مشروعًا أو اختر مشروعًا قائمًا.
2. من **APIs & Services → Credentials** أنشئ **OAuth client ID** من نوع **Web application**.
3. أضف رابط المعاينة ورابط الإنتاج الفعليين ضمن **Authorized JavaScript origins**، مثل `https://your-project.manus.space`. لا تستخدم مسارًا فرعيًا مثل `/admin` في هذا الحقل.
4. انسخ Client ID وأضفه في إعدادات المشروع تحت المتغير `GOOGLE_CLIENT_ID`.
5. لا يحتاج تدفق ID Token الحالي إلى `GOOGLE_CLIENT_SECRET`. لا تضفه إلا إذا تم اعتماد Authorization Code Flow مستقبلًا.

> في التطوير، لا يوجد تجاوز دخول تجريبي؛ غياب `GOOGLE_CLIENT_ID` يعطّل زر الدخول بدل إنشاء حساب وهمي أو تجاوز الصلاحيات.
